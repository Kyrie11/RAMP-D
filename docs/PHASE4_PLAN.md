# Phase 4 开发计划：协议分支与完整支持集验证器

**文档性质：下一阶段的实现与验收计划，尚未实现。** 本文件不把 Phase 3 的局部物理证据、有限固定点或可执行 graph 升格为完整系统证书。路线继续严格遵循上传历史 Markdown 的 `0 → 1A → 1B → 1C → 1D → 2 → 3 → 4 → 5 → 6`，本轮之后先完成 Phase 4，再进入完整 CEGAR 和数据实验。

依据为用户单独上传的论文、历史设计记录中的 Phase 4/5/6 定义，以及本项目 `MATHEMATICAL_CORRECTIONS_PHASE3.md` 中已说明的数学修正。历史记录约第 4275—4287 行将 Phase 4 定为 Protocol automaton、Rule event、Resource state、Agent reachable tube、Observation branches、Continuous collision 和 Terminal invariant membership 的连接；约第 4289—4298 行将完整 CEGAR 留给 Phase 5。

## 1. 本轮目标与交付边界

Phase 4 的目标是：给定明确的协议、初始联合支持、候选公共策略和模型契约，对协议允许的**全部离散分支**及其**全部连续不确定性**完成安全和终端义务检查，输出语义严格的 `CERTIFIED / COUNTEREXAMPLE / UNKNOWN`。

这里的“完整”相对于显式声明的协议和物理模型，不是相对于所有现实道路行为。论文条件性结论依赖实际演化被协议和车辆/他车外包围覆盖；协议遗漏、扰动界失真或观测模型失真不能由更多单元测试补救。

本轮应交付：

1. 有限协议分支、消息与观测的因果转移契约及其实现。
2. 动态资源、完整车身占用、容量/冲突和资源监视器。
3. 受 ego 策略影响的他车保守轨迹管接口与至少一种可验证的合成模型。
4. 覆盖协议乘积的验证队列、连续时间检查和单个终端支持检查。
5. 与当前公共控制器、证据上下文和 policy graph 接口衔接的证书与回放。
6. 具体反例的独立检查接口、未决义务报告及失败案例集。
7. 一键验证、验收报告与实际计数的测试/分支覆盖记录。

Phase 4 不承担训练预测器、CARLA/SUMO 联合仿真、连续参数空间完备控制综合，也不提前实现完整 master problem—refinement—reverification 的 CEGAR 循环。有限候选搜索失败仍然只是“没有找到已验证候选”，不能推导“公共控制器不存在”。

## 3. 开工前冻结的输入/输出契约

### 3.1 输入

必须显式给出以下数据，并纳入可复现 manifest：

- 初始公共时间、ego 状态支持和测量误差、联合隐藏支持；每个 atom 关联协议模式、资源/监视器状态、他车状态与消息状态。
- 外部事件与流量触发事件的自动机、守卫、复位、允许时间区间、同时事件顺序及消息发布/传递规则。
- 地图坐标系、车辆参考点和完整 footprint 参数、资源多边形、方向、容量单位与冲突关系。
- ego 与他车模型、扰动界、控制界、摩擦/状态约束及连续时间外包围方法。
- 观测函数或保守集合关系、遮挡/可见性、传感误差、消息版本及当前已收到历史。
- 候选 policy graph、决策周期和采样保持语义、规划时域、终端支持与其已验证公共上下文。
- 验证预算：墙钟时间、最大待验证节点/证据数量、积分与分裂上限；任何截断均需保留未决义务。

对于支持集中可能出现但该实现尚不能表示的协议模式或他车动力学，必须拒绝该模型契约，或者返回明确的 `UNKNOWN / UNSUPPORTED_MODEL`。不能把它转换成“没有这个分支”。

### 3.2 输出

每份结果至少记录：status、assurance scope、契约及初始支持 digest、策略 digest、处理/待处理分支数、未决义务、预算和耗时、最早失败/未决时间区间、终端节点与 backup 引用。`CERTIFIED` 还须附可回放的覆盖与安全证据；`COUNTEREXAMPLE` 须附原模型可实现性证明；`UNKNOWN` 须给出造成不确定的具体原因，不能作为可执行策略的安全标记。

非法 NaN、缺失必需字段、维度错误和自相矛盾的时间规范属于输入拒绝，不应伪装成一个已审查过的正常安全结果。

## 4. 有限协议乘积与因果顺序

验证节点应覆盖至少以下乘积因素：

\[
\text{protocol modes}\times\text{joint information cells}
\times\text{resource-monitor modes}\times\text{continuous tubes}.
\]

有限性来自明确的有限离散模式、有限规划时域，以及协议给出的有限事件数上界、最小驻留时间或经过证明的有限抽象。事件时间、初始状态和扰动通常仍是连续集合，必须用区间和验证管包络，不能靠随机采样变成“完整覆盖”。

若模型允许时域内无限跳变而实现尚无相应闭包证明，应拒绝该契约或保持 `UNKNOWN`。不能以代码的队列上限替代协议中的事件上界；到达实现预算时队列不再为空意味着尚未证完。

按论文 `eq:causal-transition` 保持转移顺序：

1. 外部事件按外生上下文演化；不把候选未来 ego 控制当成外部事件无条件发生的原因。
2. 流量触发事件读取当前交通流及控制器上下文，其中流量包含 ego 的贡献。
3. 更新交互让行关系，再依据正式规则更新资源。
4. 他车响应依据 ego、资源和交互关系演化。
5. 更新消息队列、资源监视器及实际可收到/可看到的观测。

实现可在更细时间尺度上展开，但不能颠倒因果关系。预测概率只可决定验证顺序或任务成本，不能删除低概率但允许的安全分支。联合相关性必须保留；采用更大的笛卡尔积外包围是保守但可能导致 `UNKNOWN`，采用只保留最可能组合的近似则不能支撑完整认证。

## 5. 四时钟、effective interval 与 silence

四时钟指四类应独立记录的时间，不能从其中一个字段猜出其他字段：

| 时间 | 含义 | 能否直接进入 ego 的公共观测历史 |
|---|---|---|
| `t_change` / 实际生效时间 | 环境或正式资源状态真正发生变化的时间 | 不能仅因变化发生就认为 ego 已知 |
| `t_issue` | 有关消息被发布的时间 | 不能；发布不等于接收 |
| `t_receipt` | 消息抵达 ego 的时间 | 可以，从实际收到时开始可用 |
| `t_local_first_observation` | ego 首次能够本地观测到相应变化的时间 | 可以，按可见性、误差与观测模型加入 |

此外，每条消息必须保留它声称的有效区间 `[tau_on, tau_off)`、内容、版本、来源及有效性/撤回规则。**消息的 effective interval 是独立语义字段**，不能自动与实际 `t_change` 相等。提前公告、延迟发布、失效消息和版本更替均须由协议说明；不应擅自加入 `t_issue >= t_change` 限制，以排除合法的提前通知。正常无时钟误差模型下接收不得早于发布；若考虑跨源时钟误差，其界也需进入契约。

发布延迟 `t_issue - t_change` 和传递延迟 `t_receipt - t_issue` 不可合并。真实物理变化后，消息可以尚未发布、在途或丢失，本地还可能被遮挡。

`silence` 必须作为观测覆盖中的真实分支。没有明确发布保证时，未收到消息不能删除“变化已经发生”分支。即使有发布期限，若没有相应传递/不丢包保证，未收到也通常不足以排除变化。只有完整协议能证明“若该变化已发生，则到当前时间必然已收到或已可观察”，才可据 silence 排除相应历史。

消息乱序、重复、旧版本晚到、公告取消以及 receipt 与局部观测同时发生时的处理，需要可测试的确定性规则或完整枚举其允许顺序。不得由 Python 字典遍历顺序决定协议语义。

## 6. 资源与 footprint 的完整约束

每个资源遵循论文 `eq:resource-state`：

\[
R_r(t)=(\alpha_r(t),\beta_r(t),d_r(t),\kappa_r(t),p_r(t)).
\]

- `alpha` 只决定新进入许可。
- `beta` 决定已经在资源内的车辆能否继续占用并清空。
- `d` 为允许行驶方向，不能用无向几何邻接替代。
- `kappa` 为整数容量，需求 `n_ir` 与其使用同一单位。
- `p` 为资源控制器状态；交互让行关系单独表示，不能把“他车愿意让行”变成正式通行许可。

占用必须由完整车身与资源多边形相交得出：

\[
c_{ir}(t)=\mathbf1[F_i(t)\cap P_r\ne\varnothing].
\]

车头已经进入而后轴/中心尚在外时，仍属于占用。对外包围只能证明“可能占用”时，容量与冲突检查应保守处理，或进一步细化；不能把“不确定是否相交”解释成“未占用”。

容量和成对资源冲突分别检查：

\[
\sum_i n_{ir}c_{ir}(t)\le\kappa_r(t),
\qquad
c_{ir}c_{js}=c_{is}c_{jr}=0,
\quad\{r,s\}\in\mathcal X,\ i\ne j.
\]

冲突应覆盖两个方向，且限制不同车辆。一辆长车跨越相邻资源不自动构成两车冲突；同一车在每个实际占用资源中仍要正确贡献该资源的负载。新 ego 进入时的容量检查使用 `L_r,-0 + n_0r`，避免将 ego 重复计数。

资源监视器必须保留进入前后状态，从而区分 `alpha=0,beta=1` 的“禁止新进入但允许在内车辆清空”和 `beta=0` 的继续占用禁令。入口 availability 只是必要筛选，仍需验证整个进入、占用与离开期间的动态规则和连续碰撞。

若使用论文的时间窗口预筛选，占用时长必须有经过证明的区间 `[T_min,T_max]`；退出窗口须覆盖所有可能的退出时刻 `t+[T_min,T_max]`，不能只检查 `t+T_max`。预筛选成功不替代全轨迹验证，失败不证明所有其他候选不可行。细节见数学修正说明第 5 节。

## 7. 他车轨迹管与连续时间证据

他车模型至少要接收联合源支持、ego 候选控制/可达管、资源状态和交互关系；输出必须外包围该模型允许的所有他车响应。可以先使用合成的有界加速度/响应模式模型，但必须声明状态参考点、扰动、控制和相关性。不能把录制轨迹、名义预测线或单个采样响应当作响应集合的外包围。

对于 ego 改变间距或进入资源后会引起他车反应的场景，不得继续复用与 ego 无关的窄预测管。若模型将他车表示成不依赖 ego 的更大管，并能证明该管涵盖所有允许反应，这种保守方法可以作为首版；缺少该包含依据时只能 `UNKNOWN`。

ego 和他车均须在整个验证子区间上生成 swept footprint。严格正的分离下界可以证明碰撞约束通过；接触或分离下界不正仅代表尚不能证明安全，需要具体化或返回未决，不能从外包围相交直接宣称真实碰撞。

继续复用 Phase 1B/1D/3 的定向舍入、Picard 包含证据和独立解析 tightening。任何 tighter bound 必须使用与原证据一致的起点、输入、扰动和时间域；解析公式只在它的已检查前提下适用。不能通过截断负速度、缩小扰动、只取子段端点或任意 epsilon 改善验收结果。

## 8. 观测因果性与整体后验

观测分支必须由协议消息队列、ego 位姿、遮挡/可见性、传感器误差等模型推导，替代人工声明标签覆盖。每条可实现历史至少被一个允许观测分支覆盖；重叠的保守标签可导致额外后验，但不能遗漏原本可能的观测。

在消息收到或本地观察实际可用之前，策略节点不能按隐藏事件分开动作。同一已实现观测历史必须使用同一控制律和恢复选择。为了积分或检查事件而分裂时间段，**不自动增加控制更新机会**：默认仍按已声明周期采样并零阶保持。若要支持事件触发重规划，必须另行明确其观测到达、控制延迟及保持语义并验证。

每个实际观测 `Y` 下，先将所有兼容源 atom 和全部协议后继合并成后验，再检查终端：

\[
\forall Y\text{ with nonempty posterior},\quad
\exists B_Y\in\mathcal S_{\rm in}:\quad
\operatorname{Post}_{\mathcal P}(B,\kappa,Y)
\subseteq\gamma(B_Y).
\]

目标 `B_Y` 必须具有兼容的公共时间、协议时钟、已观测信息和证据契约。不同观测可以选择不同目标；同一观测不能给每个隐藏模式偷偷选择不同控制。由多个目标的物理并集覆盖后验不满足这一量词。

Phase 3 的 graph 可以提供控制律与候选终端结构，但进入 Phase 4 后必须在完整协议和他车模型下重新验证每条保留转移及固定点闭包。终端集合不是一次有限停止 rollout，也不是无协议上下文的静止点；涉及非零扰动、未来封闭或资源变化时，必须证明其公共 backup 在对应支持上持续有效。

## 9. 三值结果与反例真实性

| 结果 | 必须满足的条件 | 不足以得出该结果的现象 |
|---|---|---|
| `CERTIFIED` | 所有允许协议分支已覆盖；所有连续管满足硬约束；所有非空观测后验属于一个兼容的已验证终端支持；队列为空且未决义务为空；证据能独立回放 | 只有采样轨迹成功、只有入口可用、固定点非空、没有发现碰撞、队列因超时被清空 |
| `COUNTEREXAMPLE` | 存在满足原动力学、协议、观测和同一候选策略的可实现轨迹/信息状态，且有已验证的约束或所承诺终端条件违反 | 外包围交障碍、分离证明失败、终端外包围过宽、仅不满足抽象目标的一个虚假标签 |
| `UNKNOWN` | 无完整安全证明，也无已确认具体反例；原因包括外包围过宽、终端包含未决、未决具体化、未覆盖模型、预算耗尽 | 不能将其当作安全，也不能将其等同“系统必然不安全” |

具体化验证器必须核查候选反例的初态、每段动力学/扰动、事件时间与守卫、消息发布/接收、实际观测及公共控制选择。数值仿真轨迹或优化器的浮点返回值只能是候选，仍需独立可实现性/违反验证。初版可以对有限、解析可解的基准给出准确具体反例；不要求对任意非线性实例作出决定。

特别地，**外包围终端失配只能产生未决义务或 `UNKNOWN`，不能直接产生 `COUNTEREXAMPLE`**。若声称信息状态终端失败，需要证明有关公共观测下的可实现信息状态未满足终端条件；不能只选取一个隐藏状态就绕过公共控制要求。终端条件失败也应与物理碰撞失败分别标注。

若已经发现一个充分验证的具体反例，可结束该候选的验证；发现反例之前尚存其他未决分支不妨碍“该候选存在反例”的结论。相反，`CERTIFIED` 必须完成全部义务。

## 10. 时间边界与预算语义

事件时间为区间时，应在最早/最晚可能时刻、消息有效区间端点、接收/观测窗口边界及控制采样点划分检查区间。对可能的离散跳变核查前后状态，明确半开区间的端点归属。若多个事件同时可能发生，枚举协议允许顺序或使用经证明等价的同步转移，不能丢弃边界事件。

时间表示须保留输入的精确语义。可复用 `Fraction` 表示可精确比较的采样/事件时刻，或使用有方向舍入的时间区间；不能让 `t+h` 的普通浮点累计误差将事件移到错误一侧。连续子段不能留下时间空隙，不能因重叠端点重复执行离散事件。外包围构造、解析 tightening 和证据回放使用相同时间原点与范围。

队列至少记录未决事件时间、源信息节点和剩余义务。建议按最早未决事件时间再按管宽排序，符合论文算法；此排序只影响效率。预算检查须覆盖开始、展开前后、积分/具体化返回后及最后一个候选完成后，不能在单次昂贵调用超预算后仍报告完整成功。

首版若内部积分/具体化不是可抢占的，报告其实际耗时和预算超出，不应称为硬实时保证。达到时间/节点/内存保护上限时，保留未决清单并返回 `UNKNOWN`；不要将剩余分支从证书删除。可恢复检查点必须绑定与原任务相同的完整契约。

## 11. 缓存、证书与执行守卫

完整证据至少绑定：源联合支持、控制律及采样语义、物理模型和扰动/测量误差、地图/footprint、全部协议自动机/时钟/消息保证、资源与监视器语义、他车模型、观测模型、分支覆盖、终端集合及其公共上下文。序列化格式和影响证据解释的版本也须固定。

digest 是内容完整性与匹配机制，不能单独证明任何安全命题。回放需要重新检查数学证据和覆盖义务；只对 JSON 算 hash、只确认引用存在或只重放局部 Picard 段都不足以支撑完整证书。

执行方应使用来自当前运行契约的 expected digest，不能只读文件内自述值再与自身比较。缓存命中还需满足当前支持位于已验证 tube/信息节点、公共时间兼容、实际消息/观测可被覆盖、控制未越过证书有效时域和采样安排。仅“同一个文件/同一个 node ID”不能证明当前场景仍受保护。

未知观测、证据缺失/篡改、时钟或版本不符、支持逸出、漏报/新消息改变支持、契约变化均应使缓存执行失效并报告原因。可以调用其他仍有效的已验证备用策略；不能在没有证据时默认为某个子节点，或以“紧急刹车通常安全”替代公共备份证书。

## 12. 必测正常例与失败案例

测试应证明语义差异，而不只复制实现分支。采用小规模、可独立枚举或解析检查的合成协议；保持无 GPU、无数据集、无模拟器依赖。

| 测试组 | 最少场景/对照 | 预期行为 |
|---|---|---|
| 三值基线 | 全分支安全小系统；原模型可实现的明确违反；人为放宽管导致无法证明但真轨迹安全 | 分别得到可回放 `CERTIFIED`、可验证 `COUNTEREXAMPLE`、`UNKNOWN` |
| silence | 实际已封闭、尚未发布/接收且被遮挡；与具有完整发布及传递保证的对照 | 无保证时保留封闭分支；有保证时只按可证明的期限排除 |
| 四时钟/版本 | 提前公告、延迟发布、晚到旧版本、乱序/重复消息、有效期端点 | 仅在实际可用时更新公共历史；规则状态和消息状态分别处理 |
| 不提前分支 | 两个隐藏事件在接收前不可区分，收到后可区分 | 收到前动作相同；之后才允许不同公共后继 |
| 资源 alpha/beta | 禁新入但允许清空；禁继续占用；单纯他车让行 | 分别检查入口与持续占用；让行不创造正式许可 |
| footprint 与容量 | 车头越界但参考点未越界；长车跨资源；ego 进入计数；容量单位错误 | 用全车占用；不制造同车冲突；不重复计数；错误契约拒绝 |
| 冲突方向 | 交换冲突资源和车辆索引的等价实例 | 两个方向均受约束，不因标签顺序漏检 |
| ego 影响他车 | ego 不进入/进入导致他车可允许响应不同；某分支仅低概率 | 管覆盖全部允许响应，低概率分支仍验证 |
| 连续时域 | 两车在子段中间碰撞但端点分离；资源在中途失效 | 不因端点安全而认证；区分真实违反与过宽外包围 |
| 整体后验 | 同一 silence 后验的两个隐藏模式分别属于不同目标，但不存在一个目标容纳全部 | 不接受目标并集拼接；保持未决或验证信息状态反例 |
| 终端外包围 | 真后验位于终端，外包围超出；扰动下有限停车但无不变驻车支持 | 前者不能误报具体反例；后者不能当递归终端证书 |
| 时间边界 | 事件在区段起点/终点、两事件同时发生、非二进制小数周期、狭窄事件窗口 | 不漏分支/时间片，不提前控制，不错误处理半开区间 |
| 覆盖与预算 | 少一个允许分支；最后一次操作超时；节点上限；具体化未决 | 不产生 `CERTIFIED`；报告 `UNKNOWN` 及实际剩余义务 |
| 缓存与执行 | 修改协议/扰动/观测/资源/终端任一项；未知观测；错时执行；支持逸出 | expected contract 不匹配或守卫失败，停止使用失效证据 |
| 确定性回放 | 相同规范重复运行；改变数据排列但保持同一语义；证据字段篡改 | 结果可解释、摘要规范化；篡改不能通过回放 |

测试数量不是安全证明。验收报告应同时给出实际用例数、无跳过情况、每类义务的覆盖与证据来源，不设一个随意的通过数代替上述语义门槛。

## 13. 开发顺序与验收 gate

继续用户指定的顺序：**明确本轮目标 → 实现代码 → 执行测试 → 分析失败案例 → 形成验收报告**。

建议将 Phase 4 内部工作组织为以下顺序，不新增或改变外部阶段编号：

1. 冻结协议/时钟/资源/观测/他车接口和可独立穷举的最小基准，先记录所有假设与预期状态。
2. 实现协议与消息转移、资源监视器和联合观测更新，验证离散分支覆盖及非预见性。
3. 接入 ego/他车连续管和完整 footprint，验证事件区段的全部硬约束。
4. 接入整体后验、单目标终端检查以及在完整协议下重新验证的 backup graph。
5. 实现三值队列、最小具体化检查器、证据回放、缓存与执行契约守卫。
6. 执行全工程回归、专门失败案例和预算实验，逐项解释失败原因，形成 Phase 4 本地验收及服务器待验收报告。

只有以下 gate 全部满足，才可宣称 Phase 4 在**所声明模型和有限基准**上通过：

- Phase 0—3 已有构建、数值、物理证据、固定点和 graph 回放回归全部通过；验收入口继续不依赖 tex/bib。
- 最小协议基准能以独立枚举结果核对全部分支；有完整 coverage ledger，不以采样概率或观测标签数量代替覆盖。
- 上表每类反例与正常对照均落地，通过实际测试执行；关键组不能 skip。
- 三种结果各有独立可复核例子；外包围碰撞/终端失配均不会自动变成具体反例。
- 所有 `CERTIFIED` 结果具有空待验证队列和空 unresolved 集合，且全时域、全部后验与公共终端义务可回放。
- 所有 `COUNTEREXAMPLE` 都通过原模型可实现性及违反检查，包含具体契约、公共历史与策略绑定。
- 超预算、模型未支持、丢分支或未知观测均不能得到安全认证；缓存篡改、错时和契约失配测试拒绝执行。
- 报告如实记录模型范围、连续外包围保守性、有限事件假设、运行耗时和非抢占限制；服务器尚未运行时明确写“服务器待验收”。

## 14. 与 Phase 5、Phase 6 的分界

**Phase 5：完整 CEGAR。** Phase 4 必须具备三值验证与可靠的具体反例检查接口，能够保留 spurious/unresolved 抽象路径和责任位置。Phase 5 再实现完整的 concrete/spurious 分流、cell 与 observation refinement、master problem 更新、旧证据失效管理及迭代验证队列终止。Phase 4 可继续使用已有积分细分来收紧管，但不能把这种数值细分称为已完成 CEGAR，也不要求本轮实现所有未知实例的自动消除。

**Phase 6：数据训练与闭环实验。** WOMD Scenario、Argoverse 2 Motion Forecasting 接入和学习模型，以及 SUMO 1.20 / CARLA 0.9.16 无头联合仿真，按原路线在 Phase 6 正式接入。Phase 4 先产出协议 manifest、四时钟日志格式、资源/车辆参考点约定和接入接口，为届时的记录与验证做好准备。真实数据缺失的消息发布/接收与本地可见时间，不能通过轨迹或 dynamic map signal 无依据补全。

现阶段**不需要下载新增数据，也不需要启动模拟器**。已有服务器路径、WOMD/AV2 字段及参考点变换、训练/验证/测试限制和模拟器使用约定见 `DATASETS_AND_SIMULATORS.md`。该文档已明确未访问用户服务器；本计划同样不声称确认服务器安装、数据完整性或性能。
