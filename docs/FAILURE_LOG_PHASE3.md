# Phase 3 失败案例与修正记录

本轮遵循“目标 → 实现 → 测试 → 失败分析 → 验收”的顺序。下面区分代码缺陷、
数值外包过宽造成的误拒、测试期望错误，以及应当保持的 UNKNOWN。完整测试
结果由本轮自动生成的 `pytest.xml` 和验收摘要记录。

## 1. Phase 2 证据引用可迁移到不同控制

**发现：** 旧 `evidence_verifier(ref)` 只接收字符串，无法比较当前 source、
control、observation posterior 与引用证据的内容。静止自环复用同一个引用时，
把控制从 `(0,0)` 改成 `(1000,1000)`，旧固定点及回放仍可通过。

**原因：** 外部证据回放和当前待证义务之间没有内容绑定。有限图递推本身仍
是在对其输入图求固定点，但物理证据无法由该接口证明当前图边。

**修正：** 引入 `EvidenceContext`，绑定完整 belief support、policy node、
源 atom、action、公共律和全部当前 observation branches；旧 ref-only 回调
不再自动接受。新增反馈 `controller_ref`，新候选证书为 v2；v1 仅保留常数
控制兼容，不允许携带被旧解析器忽略的反馈律。

**回归：** `test_evidence_binding.py` 的控制、源支持、其他源支持、观测、后继、
反馈律和证书输入篡改测试。哈希只绑定内容，实际局部证据仍由 Picard 与
硬约束检查独立回放。

## 2. tex/bib 缺失导致数值验证整条命令失败

**发现：** Phase 2 调用 Phase 1D 验证入口，最后生成来源哈希时无条件读取
两个论文文件；全部数值测试通过后，论文文件缺失仍会导致脚本失败。

**修正：** 论文文件改为存在时附加的来源记录；代码、配置、构建文件保持
正常哈希。Phase 2 入口同时转发 CMake 参数并标准化 BUILD_DIR/REPORT_DIR。

**回归：** 独立无 tex/bib 源码副本完整运行 Phase 2 入口，使用相对 build/report
路径，并从外层传入 MPFR include/library 参数；脚本通过并生成报告包。

## 3. Picard 搜索膨胀使静止 hold 被误拒

**发现：** 为解决累计时间表示问题，一版实现以每段未经收紧的 Picard
`segment.initial` 重新计算解析界。后续段带入数值搜索盒的微小负速度，
使真实静止状态无法证明 `v>=0`。

**修正：** 解析 tube 从全步原始 source 计算，覆盖截至目标子段末时刻的
完整区间，再与原 Picard 子段 tube 相交。原数值见证保持不变。没有将负数
裁剪为零，也没有放宽安全边界。

**回归：** `test_backup_synthesis.py` 中 h=0.1、h=0.125 的静止边界，以及
`test_backup_graph.py` 中终端 hold 的闭图与重复执行。

## 4. 累计有理时间不能直接当作精确 binary64 时间

**发现：** 每个子步长度可以由 binary64 精确表示，但若干子步之和未必仍能
无误差表示为一个 binary64 数。对累计 end 直接 `float(end)` 后当作精确
解析时域，可能向下缩短应覆盖的区间；强制要求完全可表示又会不必要地拒绝
常见的非二进制整周期配置。

**修正：** 使用 Fraction 精确比较，给累计 end 构造向上的 binary64 界；
只有发生向下舍入时才用 `nextafter(+inf)` 扩一格。解析 tube 覆盖 `[0,upper]`，
因此包含该子段。这个向上时间界只用于 tube，不能误当成真实 endpoint 时刻。
全步 endpoint 仍使用配置的精确 binary64 周期。

**回归：** 非二进制周期、解析输入合法性、tube/endpoint 区分测试及 h=0.1
静止案例；推导见 `MATHEMATICAL_CORRECTIONS_PHASE3.md`。

## 5. 首个分离轴低估可证明的 clearance

**发现：** Phase 1D 的函数找到第一个有效分离轴即返回，足以证明非相交。
Phase 3 把这个轴的间距直接作为 reserve 和 minimum-clearance 检查时，会
因为一个很弱的 x 方向间距而拒绝实际存在很强 y 方向分离证据的动作。

具体反例：ego 沿 x 轴从 0 行驶到4，静态障碍在 `(2,2)`，两者均为0.2m矩形。
y 方向全程约1.8m间距，但 x 分离间距在经过障碍附近时很小。

**修正：** Phase 3 对所有候选轴分别验证，取有效间距下界的最大值。若每个
数值都是实际距离的下界，则其最大值仍为下界。原 Phase 1D 接口语义不变。

**回归：** 路径中障碍仍被拒；旁侧障碍通过且全程余量下界大于1.79m。

## 6. 自然区间时间依赖使安全停止过程被误拒

**发现：** 对 `v0=0.125, a0=-1, jerk=4, h=0.25`，真实速度为

\[
v(t)=0.125-t+2t^2=2(t-0.25)^2\ge0.
\]

自然区间计算把多个 t 独立取值，会给出虚假的负下界，阻止精确 `v=a=0`
停止目标的局部验证。

**修正：** 由 MPFR 外包得到速度上下包络的二次多项式系数，对端点和域内
驻点计算准确 Fraction 极值，再经显式有向转换给出 binary64 边界。正积分
核保证上下包络同时适用于有界可测 jerk 和导数扰动，并不要求扰动为常数。
endpoint 与 tube 的含义仍分别处理。

**回归：** 精确停止边界、二次顶点、受扰上/下界和极小数值等测试；实际
Brake → Stop → Stop 图可回放并执行。该修正提高可证明能力，没有使用容差
或速度剪裁。

## 7. 只在候选开始时检查软截止时间

**发现：** 若最后一个或唯一一个候选内部耗时超过预算，原先只在候选开始
前检查时间的方式可能把超时搜索记录为正常完成。

**修正：** 候选完成后再次检查截止时间。已有有效候选时返回 `PARTIAL_SEARCH`，
没有有效候选时返回 `UNKNOWN_BUDGET`。候选数限制与积分步数/次数限制也
独立保留。

**回归：** 只替换搜索模块的时钟，实际 MPFR 计算与证据回放仍运行；检查
最后候选内部超时的两种状态。本预算为非抢占式离线预算，不宣称硬实时性。

## 8. 手工构造 dataclass 图绕过加载器

**发现：** 可序列化的 `BackupPolicyGraph` / `BackupNode` 是数据容器，不能
因为它们具有正确类型就视作已经验证。若执行器只信任容器，手工截断节点或
伪造 observation children 可能绕过文件加载路径的检查。

**修正：** 执行器初始化时重新构造信息状态固定点与闭图，比较节点声明；
执行命令前继续逐条回放当前证据。初始化还要求调用方提供其当前可信契约
的 digest，不能用证书自述替代场景契约。

**回归：** 手工伪造节点、错误子节点、未保留起点、错误初始支持和契约不一致
均拒绝进入正常执行。

## 9. 节点执行律可能与 action 的证明律不一致

**发现：** 节点单独记录 `controller_ref`，动作证据也记录公共律。若仅分别
检查存在性而不比较两者，可能执行另一条已注册但未经该动作证明的控制律。

**修正：** 命令发出前要求 node/controller/action 引用一致，重新核对 law
内容摘要、bias 与证据上下文，并回放完整 source 证据。

**回归：** 改动节点 law、替换 gain/bias、删除 law、修改 record 或运行中改变
contract，均不能使用缓存图继续发出命令。

## 10. 非字符串 observation 导致异常未锁存

**发现：** `observation=[]` 等不可哈希输入如果直接参与字典查找，会触发
普通 TypeError，无法保证执行器统一进入失证状态。

**修正：** 显式验证 observation 为非空字符串；未知、空或非法 observation
统一通过执行器失败路径锁存 `lost`。不自动选择默认子节点。

**回归：** 未知字符串、空字符串、None、列表，以及提前/延后 observation、
重复 command 和越界 posterior，均按相同失证语义处理。

## 11. 成功标记和重新计算哈希不能替代数学回放

**风险场景：** 调用方可以伪造 `StepCheck(status=VALIDATED_LOCAL)`，也可以
修改 JSON tube 后重新计算记录哈希。二者都不足以说明源、控制和后继的
物理关系正确。

**实现与回归：** `LocalEvidenceStore.verify` 重新比较当前上下文、契约、law
及 horizon/W/E，并执行实际 Picard/硬约束回放；空 proof、错误初态、修改
后的 endpoint 或不一致余量均不被接受。完整源覆盖必须存在，缺失某一源
检查不能注册为完整动作。

## 12. 修正一项测试期望

穿越障碍测试最初只接受“分离未证明”原因。正安全间距阈值可能在实际
外包络相交之前就已不足，因此 `SPATIAL_CLEARANCE_NOT_PROVED` 同样正确。
测试现接受这两个原因，仍严格要求整条动作不能被验证。没有修改正确的
保守算法来满足特定原因字符串。

## 13. 应当保持的 UNKNOWN

以下情况属于正确拒绝，不能为了演示成功而放宽检查：

| 场景 | 当前阶段的正确处理 |
|---|---|
| gate 位于车辆完整 footprint 内或余量不足 | UNKNOWN，不只检查后轴中心 |
| 静态障碍阻断扫掠路径 | UNKNOWN，首尾都安全也不能替代连续时间检查 |
| 摩擦可行性无法证明 | UNKNOWN，不把场景 mu 任意增大 |
| source 含待传播的 other-agent 状态 | `OTHER_AGENT_DYNAMICS_REQUIRE_PHASE4` |
| 任一源 atom 无有效公共控制证据 | 拒绝整个 belief 的该候选 |
| 同一 observation 的完整后继只能分散装进不同 target | 拒绝，不允许提前识别隐藏源 |
| 有界非零过程扰动下，精确静止点的后继已经变宽 | 不接受精确点自环，不把速度/加速度裁回0 |
| 积分或候选预算耗尽 | UNKNOWN 或带有效部分解的 PARTIAL_SEARCH，不宣称不存在解 |
| 无法回放、契约变化、观测或执行时间不匹配 | 执行器失证并报错，不自动执行未经证明的默认动作 |

Phase 3 的 UNKNOWN 尚未分类为 Phase 5 的真实/伪反例。完整支持验证和具体
反例确认仍按原路线分别属于 Phase 4 和 Phase 5。

## 14. 验收边界保持明确

本轮没有把四个单步模板写成完整驾驶任务，没有把零扰动闭图写成无限受扰
驻停，也没有把抽样零漏包写成形式证明。原生 ABI 保持3，目标服务器环境
不要求升级；本地官方 MPFR 4.2.2 的结果与用户 MPFR 4.0.2 服务器复核分别
记录。tex/bib、数据集和模拟器进程均不是本轮代码验收的运行依赖。
