# Phase 3 公共控制综合与局部证据：独立测试记录

## 1. 本轮目标

独立审阅 `backup.py` 与 `control.py`，使用真实 MPFR/Picard 后端验证有限候选
公共反馈律的综合、连续时间硬约束检查、信息状态语义与证据内容绑定。
测试文件为 `tests/test_backup_synthesis.py`。本记录仅覆盖该文件的 29 个用例，
完整 Phase 3 结论以最终集成验收报告为准。

## 2. 测试范围

| 风险 | 回归检查 |
|---|---|
| 搜索结果错误排序或只保留一种续接 | 两个实际可验证公共律按空间余量下界排序，并保留备选；逐条证据回放 |
| 根据隐藏源状态分别选择当前控制 | 一个源 atom 违反 gate，整个 belief 的当前 law 必须拒绝 |
| 同观测提前分支 | 两个源 atom 的同名 observation 必须共同进入一个 target belief；分别进入两个 target 不通过 |
| 合法观测分支 | 声明不同 observation 时可分别续接；合并 target 的 union support 可覆盖同名 observation |
| 忽略测量误差或非零反馈增益 | 非零速度/加速度反馈增益及速度测量误差参与 control image；完整源支持证据回放 |
| 把后轴位置当成车头位置 | 正确车身中心 offset 下车头越 gate 被拒；同样后轴点、不同明确几何配置的中心参考案例可通过 |
| 忽略摩擦限制 | 状态在独立坐标边界内，但低摩擦圆约束无法成立时返回 UNKNOWN |
| 只检查首尾碰撞 | 从 x=0 行驶到 x=4，中途 x=2 静态障碍被拒；首尾都分离也不能通过 |
| 过弱的单轴间距估计 | 障碍位于 y=2 时，全程至少约 1.8 m 的 y 轴余量能被验证，不被瞬时很小的 x 轴余量误拒 |
| 零速度边界被数值膨胀污染 | h=0.1 和 h=0.125 的静止 hold 均证明 v=a=0；不使用 epsilon 或状态剪裁 |
| 停止过程时间相关性丢失 | 精确二次速度 v(t)=2(t−0.25)² 的停止过程通过全程非负速度检查，并达到 v=a=0 |
| 假装已实现移动他车模型 | source 含 other-agent 连续状态时明确 UNKNOWN，等待 Phase 4 |
| 不完整积分或候选预算 | Picard 步数不够时不注册证据；候选数量耗尽区分 PARTIAL_SEARCH 与 UNKNOWN_BUDGET |
| 最后一个候选内部超过软截止时间 | 实际物理求解仍运行，仅替换搜索时钟；超时后的有效/无效候选分别得到正确预算状态 |
| 证据迁移或篡改 | law、gain、h、W、测量误差、branch、source、record 任一改变，都无法复用原证据 |
| 仅依赖哈希而不回放数学证据 | 篡改 tube 后重新计算记录哈希，仍被独立 replay 拒绝 |
| 相信手工成功标记 | 伪造 `StepCheck(status=VALIDATED_LOCAL, proof={})` 不能通过 store.verify |
| 序列化丢失身份 | JSON 往返后证据可回放；律内容与保存的 digest 不一致时拒绝加载 |

以上均为明确配置的合成、局部 bicycle/static-scene 测试；没有借用真实数据集、
模拟器或概率预测来充当连续安全证明。

## 3. 失败案例分析与修正

### 3.1 静止 hold 被 Picard 搜索膨胀误拒

初次审阅期间，为避免把累计有理时刻直接舍入为单点时间，一版代码对每段
采用未收紧的原 Picard segment.initial 重新计算解析界。原始 Picard 搜索盒
存在微小负速度外包，因此从第二段开始，真实静止状态也被误判为无法证明
`v>=0`。这是保守性缺陷，不能通过裁掉负速度或加 epsilon 解决。

修正后，从全步原始 source 计算截至该段结束时刻的解析 tube；累计结束时刻
先通过 Fraction 精确比较获得向上 binary64 界，必要时只向正无穷方向扩一格。
该时间区间覆盖完整目标子段，再与原 Picard 子段外包求交。全步 endpoint 仍
使用配置的精确 binary64 决策周期。h=0.1 与 h=0.125 静止边界回归均通过。

### 3.2 首个分离轴不等于最强间距证明

车辆沿 x 轴行驶、静态障碍位于 `(2,2)` 时，y 方向一直有约 1.8 m 的间距。
原 Phase 1D 分离函数按“找到第一个严格分离轴即可返回”设计，对非相交判定
本身是正确的。但 Phase 3 把这个首个轴的间距直接作为 minimum-clearance
判据和 reserve，导致 x 轴间距接近 0 时错误拒绝整个局部动作。

修正保持底层分离算法不变，Phase 3 在候选轴上分别取得有效间距下界，使用
其中最大值。每个数值都是距离的有效下界，其最大值仍是有效下界。反例中
局部动作通过验证，记录的全程障碍余量下界大于 1.79 m。

### 3.3 正确停止过程被自然区间时间依赖误拒

取 `v0=0.125`、`a0=-1`、`jerk=4`、`h=0.25`，无扰动、直行。

\[
v(t)=0.125-t+2t^2=2(t-0.25)^2\ge0,\qquad a(t)=-1+4t.
\]

终点严格为 `v=a=0`。如果把表达式里的每个 t 都独立替换成 `[0,h]`，会得到
包含负速度的粗外包，不能证明真实成立的全程速度约束。

解析模块现对速度下、上包络二次多项式分别计算端点与区间内驻点的精确
有理极值，再以明确方向转成 binary64 区间。系数仍由 MPFR 区间运算外包，
因此同时允许有界可测 jerk 和加性导数扰动；没有假定扰动必须是常数。
该停止反例现通过真实 tube 生成、局部约束检查及回放。

### 3.4 一项测试期望修正

穿越静态障碍的测试最初只接受 `STATIC_OBSTACLE_SEPARATION_UNKNOWN` 原因。
实际算法可能先在障碍尚未相交时发现正 minimum-clearance 不足，因此返回
`SPATIAL_CLEARANCE_NOT_PROVED` 同样正确。测试改为接受两种保守拒绝原因，
并保留“整个动作必须 UNKNOWN”的核心断言。未修改算法来迎合原因字符串。

## 4. 本地实测结果

- 测试命令：`python -m pytest -q tests/test_backup_synthesis.py`。
- 后端：官方 MPFR 4.2.2 头文件与 MPFR 4.2.2 运行库，192-bit directed arithmetic。
- 最终结果：**29 passed，0 failed，0 skipped，约 0.57 s**。
- JUnit XML：`reports/phase3_synthesis_review/pytest.xml`。

上述耗时是本次测试执行耗时，不是在线控制延迟或真实车辆吞吐性能。
软截止时间不提供抢占式实时保证。完整协议/观测支持以及移动他车验证仍属于
Phase 4，本轮结果保持局部 assurance scope 和 `full_support_certified=false`。
